# Undo Obsidian Study Loop

Safely roll back `obsidian-study-loop` artifacts when the workflow was installed
or started in the wrong workspace, or when a false-start session should be
removed. Default to preservation: inventory first, explain the plan, then make
only the smallest requested change.

This skill removes plain Markdown/JSON scaffolding. It does not call external
APIs, does not use LLM APIs, and must never delete normal Obsidian notes or
unrelated workspace files.

## Resolve the Target

The skill is global, so it may be called from any directory.

1. Resolve the target workspace or vault:
   - Use explicit `VAULT_PATH` or path from the user when supplied.
   - Use the current directory if it contains `STUDY-PROTOCOL.md`,
     `_study/state.json`, or `.obsidian/`.
   - If a previous vault path is visible in the conversation, confirm before use.
   - Otherwise ask for the path.
2. If the path is outside the current workspace or requires elevated permission,
   ask for approval through the normal tool flow before editing.
3. Do not assume the current directory is the target just because the skill was
   invoked there.

## Undo Modes

Classify the request before acting:

- **Full scaffold undo**: remove study-loop setup from the wrong workspace.
- **False-start session undo**: remove one mistaken session and clear state.
- **State-only undo**: set `_study/state.json` back to `active_session: null`.
- **Pointer-only undo**: remove the study pointer block from `CLAUDE.md`,
  `AGENTS.md`, and/or `GEMINI.md`.

If the user is vague, produce a dry-run inventory and ask which mode to apply.

## Safety Contract

- Dry-run first unless the user explicitly says to apply/remove/delete.
- Never delete `Notes/`, `.obsidian/`, attachments, or ordinary Markdown notes.
- Never use destructive git commands such as `git reset --hard` or
  `git checkout --`.
- Do not remove a file unless it is clearly generated by the study loop, empty
  aside from generated content, or explicitly named by the user.
- If a file contains both user content and generated study-loop content, edit out
  only the generated block and preserve the rest.
- If uncertain, stop and ask. A safe incomplete undo is better than deleting
  user work.

## Generated Artifacts

Study-loop setup may create:

```text
STUDY-PROTOCOL.md
CLAUDE.md
AGENTS.md
GEMINI.md
_study/state.json
_study/sessions/.gitkeep
_study/sessions/<YYYY-MM-DD>-<slug>.md
_study/README.md
```

Pointer files use this exact generated block:

```markdown
## Study sessions
When I ask to study, quiz, or review notes, follow the workflow in `STUDY-PROTOCOL.md`.
```

Only remove that exact block from pointer files. If the pointer file then becomes
empty, remove the file only when it was created solely for the study loop or the
user explicitly approves.

## Inventory

Before editing, inspect and report:

1. Whether `STUDY-PROTOCOL.md` exists.
2. Whether each pointer file exists and whether it contains the exact study block.
3. Whether `_study/state.json` exists and whether it is valid JSON.
4. The current `active_session` value.
5. Session files under `_study/sessions/`.
6. Whether `_study/README.md` and `_study/sessions/.gitkeep` exist.
7. Whether likely user notes exist in `Notes/` or elsewhere. Report these as
   protected, not removal candidates.

## Full Scaffold Undo

Use this when the user installed the study system in the wrong workspace.

Plan:

1. Remove the exact study pointer block from `CLAUDE.md`, `AGENTS.md`, and
   `GEMINI.md`.
2. Remove a pointer file only if it is empty after the block is removed and was
   generated solely for the study loop.
3. Remove `STUDY-PROTOCOL.md` only if it appears to be the generated protocol or
   the user explicitly confirms removal.
4. Remove `_study/state.json`, `_study/README.md`, and `_study/sessions/.gitkeep`
   when they are generated study-loop files.
5. Remove `_study/sessions/*.md` only if the user asked for full scaffold undo
   in the wrong workspace or explicitly named those session files.
6. Remove `_study/sessions/` and `_study/` only if they become empty.
7. Do not touch `Notes/` or any note files.

After applying, print a changelog:

```markdown
## Undo Obsidian Study Loop

- REMOVED: <path> — <reason>
- EDITED: <path> — removed generated study pointer block
- KEPT: <path> — <reason>
- SKIPPED: <path> — needs confirmation because <reason>
```

## False-Start Session Undo

Use this when a session was created too early, with the wrong topic, or in the
wrong vault.

1. Read `_study/state.json`.
2. Identify the target session:
   - Use the active session if the user says "current" or does not name one.
   - Use the named session file/topic/date if provided.
3. Show the session path and topic before removal.
4. Delete the session file only if it is clearly the target false start or the
   user confirms.
5. If `active_session` pointed at the removed file, update state to:

```text
{
  "active_session": null
}
```

6. Leave other sessions untouched.

## State-Only Undo

Use this when the user says "clear state" or wants to stop tracking the active
session without deleting logs.

Set `_study/state.json` to:

```text
{
  "active_session": null
}
```

Do not delete session files.

## Verification

After applying any undo:

1. Confirm `_study/state.json` is valid JSON if it still exists.
2. Confirm removed files are gone.
3. Confirm protected note directories still exist and were not touched.
4. Print the final state in plain language.
